# publish-xhs-douyin

把做好的竖屏/横屏视频自动发布到 **小红书** 和 **抖音** 的 web 创作者后台，
通过 [Claude Code](https://claude.com/claude-code) + Claude-in-Chrome 驱动。

这是一份 **battle-tested 的操作手册**，不是一键脚本 —— 两个平台的创作者后台都用了
难伺候的富文本编辑器和异步下拉，真正的价值在于把踩过的坑写死在流程里。

## 它解决什么

关键检查点：

| 场景 | 做法 |
|---|---|
| 点击/上传持续无效 | 先核对当前工具文档和页面状态；两次无变化停止原样重试 |
| Codex视频与双封面 | 原生文件选择器上传，竖横槽独立保存并查看结果 |
| 话题看着对其实是纯文本 | XHS核对 `a.tiptap-topic`，抖音核对 `[data-mention]` 的完整文字 |
| 章节误写事实或时间错行 | 对照已批准口播；改时间后重定位行并逐条读回 |
| 定时时区不同 | 按目标日期和页面时区换算，提交前再读回，管理页核验准确排期 |
| 提交状态不明 | 查精确作品记录，不重复提交；回执与排期核验分别记录 |
| 状态文件矛盾 | 发布计划为真源，同步已有生产状态与文档摘要 |

### 双封面生成

```bash
python3 scripts/make_covers.py --video 成片.mp4 --t 24.5 --bias 0.72 \
  --title "标题" --sub "副标题" --tag "小标签" --outdir final/
```

产出 `封面图-竖3x4.jpg` (1242×1656) 和 `封面图-横4x3.jpg` (1440×1080)，
两版都满幅铺图（竖版标题叠上三分之一，横版叠下三分之一），可读性靠渐变压暗而非色块。

`--t` 选片尾标题淡入之前的一帧；`--bias` 按主体水平位置给（3:4 满幅要从 16:9 裁掉大半宽度）。

## 说明

- 操作的是**你自己账号**的官方创作者后台，等价于手动点击，只是自动化了重复劳动。
- 不涉及任何绕过登录、风控或审核的手段；密码和验证码始终由本人输入。
- 平台前端改版频繁，手册里的坐标和选择器会过期 —— 遇到对不上时以实际页面为准，
  并欢迎回来更新这份文档。

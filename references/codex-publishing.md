# Codex 双平台发布交互

开始 Codex 发布，或交互持续无效时读取。以下接口已在2026-09-05实测；调用前仍以本次工具返回文档为准。

## 当前工具与已登录会话

- 用 CUA 的当前入口选择现有 Codex in-app Browser 标签；首次调用或 reset 后严格按工具的初始化要求，读返回文档后再继续。保留用户已经登录、上传或填好的标签。
- 当前 Tab 的直接方法为 `getAXState()`、`click(indexOrPoint)`、`typeText(text)`、`pressKey(key)`。`tab.ax.*` 是旧接口，不照搬。旧 locator click 无效不能证明直接 click 也无效。
- 每次关键操作后读当前状态再定下一步。元素索引在页面变化后重新获取；封面构图用截图检查。文本输入使用当前支持的 fill 或聚焦后的真实键盘输入，读回值确认框架已保存。
- `evaluate` 只读可见 DOM；不在其中修改DOM、派发事件、调用站内API、读取框架私有状态或注入文件。旧 Claude 的 window.name、IndexedDB、系统剪贴板与 File 注入方法不移植到 Codex。

## 视频与双封面上传

优先点击当前上传按钮触发原生文件选择器。已支持的调用形态如下，`tab`、按钮索引与绝对路径均从当前任务取得：

```javascript
var pending = tab.playwright.waitForEvent('filechooser', {timeoutMs: 10000});
await tab.click(uploadButtonIndex);
var chooser = await pending;
await chooser.setFiles([absoluteFilePath]);
```

- 视频上传后等待处理并核对预览时长，再填易被重渲染清空的字段。支持文件选择器时无需文件桥或把大文件转base64。
- 抖音竖槽传真实3:4文件，横槽传独立4:3文件。切横槽时平台可能自动复制竖图，必须替换成横版。点击“上传封面”，避免误点AI参考图上传。
- 点“完成”保存；主表单两槽应显示正确缩略图、无缺失提示，检测通过。图在编辑器出现不等于保存成功；必要时重开检查人物、标题、方向与裁剪。
- 小红书使用竖图，按实际编辑器确认3:4而非假定默认比例；保存后核对缩略图及评估结果。
- 若当前工具不支持上述 API，重新读文档选择其支持的上传路径；只有确实无法完成时才请用户处理具体步骤，不把某次故障永久写成“无法自动化”。

## 话题与章节

- XHS 逐个核对真实 `a.tiptap-topic` 的文字/话题属性，DY核对 `[data-mention]`；plain `#文字`不算。先读页面限制，达到上限后不再重试。
- 下拉加载结束后按目标完整文本选，插入后马上核对；指定话题不能擅自用推荐项顶替。显示推荐项或陈旧结果时不盲选第一条。
- ≥1分钟用已核验章节表；智能摘要和章节只作草稿，先核对人物状态、事实与真实时间。
- XHS 修改分钟可能即时重排：每次变化后按标题重新定位再改秒，不沿用旧行号。保存前读全部标题+mm:ss，保存后确认“已添加N个章节”。DY也检查实际保存数量。

## 停止重复与提交验证

同一动作两次无状态变化后，检查工具文档、当前UI、焦点、遮挡、是否处理中及数量上限，选择一条
有根据的替代路径。工具初始化损坏时才 reset 并重选原标签，不刷新工作表单。不要不停重复旧接口、
创建新草稿、重传视频，或直接把问题归因于用户未登录。

提交前读回标题、实际话题、章节、封面、声明与排期。按目标日期和页面实际时区换算；XHS明确标北京
时间时填原值，DY以页面时区为准，不能固定减12小时。一次提交后观察回执，再到管理页核对精确作品
与时间。提交状态不明先检查管理页和现有草稿，禁止用再次提交测试第一次是否成功。

只有登录/验证确实需要本人、授权信息缺失或受支持交互仍无法完成时才交用户。交接前完成其余已授权
步骤，说明具体缺哪一步。用户此前已批准的内容、指定tag与排期继续有效，无需重复确认。
